## Summary
When a user is created in Payroll and assigned a role, they can authenticate through the new enterprise
portal, complete the forced password change, and select the business — but the **Enterprise Module
Launcher renders "No modules found"**. There is **no Payroll module tile to launch**, so the user is
stranded at the launcher and can never open the Payroll application. Provisioning a user in Payroll does
**not** grant that user the Payroll **module** at the enterprise/identity level — the two are separate,
and nothing bridges them at creation time.

Confirmed across the privilege range: **Payroll Admin** and **Payroll Employee** were both onboarded
end-to-end and **both** see the empty launcher — so this is **systemic**, not role-specific.

## Steps to Reproduce
1. Create a user in Payroll (`POST /users`) and assign a role (`POST /roles/{id}/assign-users`).
2. Log in as that user at `https://sbxkedebah-v2.npontu.com/clients/sign-in`.
3. Complete the forced "Change Password" (`/clients/change-password-required`).
4. Land on the Enterprise Module Launcher (`/R-2171-WRY/clients/select-module`), business = William & Co.
5. Observe **"No modules found"** under "Enterprise Modules" — no Payroll tile.

## Expected
A provisioned Payroll user (with a payroll role) should see the **Payroll module** in the launcher and be
able to launch it into the Payroll application.

## Actual
The Enterprise Modules list is empty ("No modules found for ''"); the user cannot enter Payroll.

## Impact
**Critical — every newly-created user is unusable.** They have a valid account and a role but **zero
module access**, so they cannot do any work in Payroll. This blocks all real onboarding and also blocks
per-role permission-enforcement testing (which needs a Payroll session).

## Root Cause (suspected)
Enterprise module entitlement is managed separately from the Payroll role; creating a payroll user does
not provision the Payroll module for them in the enterprise portal.

## Suggested Fix
Auto-provision the Payroll module entitlement when a Payroll user is created (or expose a step to grant
modules to a user), so a newly-created+role-assigned user can launch Payroll.
