## Expected (per PRD §11)
"SSF Contribution — Auto-calculated from the employee's actual **Tier 1 + Tier 2** employee
contributions this month — no manual amount."

## Actual (live)
SSF relief = Tier 1 + Tier 2 + **Tier 3 (voluntary)** employee contributions.
Example — Johnson S. Abossey (basic 2,500): Tier1 EE 137.50 + Tier2 EE 0 + Tier3 EE 125 →
`ssf_employee = 262.50` (PRD-literal would be 137.50).

## Analysis
For employees enrolled in a Tier 3 voluntary scheme, the engine grants SSF relief on the Tier 3
contribution too, lowering the PAYE base (and thus PAYE) versus a literal reading of PRD §11. This
matches Ghana practice (relief for approved Tier 3 contributions within limits), so the **app is
plausibly correct** and **PRD §11 likely under-documents** the Tier 3 inclusion. Employees without
Tier 3 are unaffected (SSF == Tier1+Tier2, verified PASS).

## Evidence
- `evidence/network/run-80-employees-full.json` (Johnson, Vivian: tier_3 EE line + ssf_employee)
- Recorded FAIL: `test-management/test-execution-report.md` (feature "SSF relief composition")
- Spec: `automation/tests/payroll/calc-coverage.live.spec.ts` (expected-to-fail test)

## Suggested Resolution
Confirm whether Tier 3 should attract SSF relief. If yes (likely), **update PRD §11** to
"Tier 1 + Tier 2 + Tier 3 employee contributions". If no, fix the relief engine. Note interaction
with the 35% pension cap (§17) which already bounds total relief.
