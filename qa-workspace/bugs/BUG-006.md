## Summary
Created pay group #1 ("ZZ-QA-Group") but the member assignment did not persist (`employee_count` = 0,
`members` empty). A **Regular** pay run (#86) created with `pay_group_id = 1` then populated **all 4
active-salary employees** (Asibe, Johnson, Khalifa, Vivian) and was carried through to Paid.

Per PRD §5: *"creating a run for a pay group adds its members automatically; a regular run with no pay
group adds all employees with an active salary."* So a run scoped to a pay group should add the
**group's members** — an empty group should add **0**, not all active-salary employees.

## Steps to Reproduce
1. Create a pay group (members empty / failed to attach).
2. Create a Regular pay run with that `pay_group_id`.
3. Process → observe the populated employees.

## Expected
The run includes only the pay group's members (0 for an empty group), per PRD §5.

## Actual
The run populated all 4 active-salary employees (the "no pay group" behavior), despite being linked to
a specific (empty) pay group.

## Caveat / why "needs confirmation"
The pay group was empty because the member-add contract wasn't correctly identified (create body field
`member_staff_ids` did not attach members; `POST /pay-groups/{id}/members` had no effect). A clean
confirmation requires a pay group populated with a **strict subset** of active employees, then verifying
the Regular run includes only that subset. That is blocked until the pay-group member-assignment
contract is captured. Logging now because the observed "empty group → all active employees paid" is a
real risk (a user could unexpectedly pay everyone).

## Suggested Fix / Next Step
- Confirm the pay-group member-assignment API, build a 1-member group, and re-run.
- If reproduced with a non-empty subset group being ignored → real scoping bug (raise severity).
- Engine should treat a pay-group-scoped run as "members only" (empty group → empty run, with a clear warning), not silently fall back to all-active.

## Evidence
- pay group #1: `employee_count` 0, members empty.
- run #86: `pay_group` = {id:1}, `total_employees` = 4, status Paid.
